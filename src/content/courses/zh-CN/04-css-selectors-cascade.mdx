## 概述

HTML 说明事物*是什么*，CSS 说明它们*长什么样*。到目前为止，本课程的每个页面都穿着浏览器的默认外观——黑字、蓝链接、衬线字体。这一课把画笔交给你。

CSS 的全称是 _Cascading Style Sheets_（层叠样式表），每个词都有分量。_Sheets_（表）是一串规则；_style_（样式）是一组描述外观的属性值对；_cascading_（层叠）则是当两条规则打架时的和解协议。夹在中间的是选择器——规则里决定"作用于谁"的那部分。

选择器是你今后敲得最多的语法。学完本课，你能按类型、类、id、元素间关系乃至当前状态（比如被悬停）选中元素，还能在多条规则同时命中时*预判*谁会获胜。练习会把这套工具放到同一个三卡片页面上逐一用上。

## CSS 的写法与接入方式

每条 CSS 规则形状相同：一个选择器，加一对装着声明的大括号：

```css
selector {
  property: value;
  another-property: another-value;
}
```

选择器回答*对谁*；声明回答*做什么*。每条声明都是一个以分号结尾的 `property: value` 键值对。一条具体的规则，作用于页面上每个 `h1`：

```css
h1 {
  color: darkblue;
  font-size: 32px;
}
```

规则要送到浏览器手里才有用。把 CSS 接入页面有三种方式：单个元素上的 `style` 属性（`<p style="color: darkblue;">`）、head 里存放整页规则的 `style` 元素，以及用 `link` 元素连接的外部文件：

```html
<head>
  <style>
    p {
      color: darkblue;
    }
  </style>
  <link rel="stylesheet" href="styles.css" />
</head>
```

`style` 元素把规则直接放在页面内部；`link` 让许多页面共享同一份样式表，是专业上的默认选择。在内置编辑器里，CSS 窗格已自动接入预览，直接写规则就能看到效果——这里学到的内容对三种接入方式同样适用。

> **动手试一试：** 在编辑器的 CSS 窗格里写一条规则，把 `h1` 变成 darkblue 并设 `font-size: 32px`。预览后换个颜色，看页面随着每次敲键重新上色。

## 基础选择器

三个选择器覆盖日常样式的大部分。它们各自问元素一个不同的问题：

| 选择器        | 问的问题                        | 示例                          |
| ------------- | ------------------------------- | ----------------------------- |
| 类型 - `p`    | 你是这个类型的元素吗？          | 所有段落                      |
| 类 - `.intro` | 你的 `class` 里包含这个名字吗？ | 任何带 `class="intro"` 的元素 |
| id - `#top`   | 你是那个带此 id 的唯一元素吗？  | 单个唯一元素                  |

同一套选择器用在真实标记上：

```html
<h1 id="site-title">Field Notes</h1>
<p class="intro">Every morning, at the pond.</p>
<p class="intro">The rules are simple.</p>
```

```css
h1 {
  font-size: 28px;
}

.intro {
  color: #444444;
}

#site-title {
  color: darkblue;
}
```

关于如何取舍：类可以复用——一个类对应任意多个元素，一个元素也可以携带多个类。id 在页面内必须唯一，最好留给 JavaScript 钩子和独一无二的地标。拿不准时，用类来写样式。

选择器还可以用逗号共用一个声明块，让相同样式保持同步：

```css
h1,
h2,
h3 {
  color: darkblue;
}
```

> **动手试一试：** 在编辑器里给两个段落加同一个 `intro` 类，只写一次类样式。再给其中一个段落加第二个类，并为它配不同颜色——一个元素、两个类、同时生效。

## 组合器与伪类

当选择器描述*关系*时，它会变得更锋利。两个选择器之间的空格是后代组合器——匹配任意深度之内的元素：

```css
/* every h2 anywhere inside .card */
.card h2 {
  color: darkblue;
}

/* only p elements that are direct children of .card */
.card > p {
  color: #444444;
}
```

子组合器 `>` 是更严格的版本：只匹配直接子元素，再深一层的嵌套就管不到了。实践中，后代组合器是日常之选，子组合器是在嵌套变深时才动用的手术刀。

伪类为选择器增加了一个标记无法表达的维度：元素的*状态*。它们以冒号开头，描述的是时刻而非结构：

| 伪类           | 匹配时机                   |
| -------------- | -------------------------- |
| `:hover`       | 指针悬停在元素上           |
| `:focus`       | 元素正等待键盘输入         |
| `:first-child` | 元素是父元素的第一个孩子   |
| `:last-child`  | 元素是父元素的最后一个孩子 |

```css
.card:hover {
  border-color: royalblue;
}
a:focus {
  outline: 2px solid royalblue;
}
li:first-child {
  font-weight: 700;
}
```

这是一种安静的超能力：一条规则就能描述原本需要 JavaScript 的交互。浏览器替你盯着鼠标和键盘，在状态成立时精确应用规则，状态结束时立刻撤下。

> **动手试一试：** 在编辑器里给某个段落加一条 `:hover` 规则改变颜色。在预览里悬停、移开，观察状态的应用与解除。

## 层叠与优先级

迟早会有两条规则想同时给一个元素上样式。层叠就是浏览器裁判时的那套规则，逻辑很短。

第一，_更具体者胜_。优先级记作三个数字——id、类、类型——得分更高的选择器拿下元素：

| 选择器        | 得分（id, 类, 类型） |
| ------------- | -------------------- |
| `p`           | 0, 0, 1              |
| `.card`       | 0, 1, 0              |
| `.card h2`    | 0, 1, 1              |
| `#site-title` | 1, 0, 0              |

一个类胜过任意多个类型；一个 id 胜过任意多个类。看它在行动：

```css
p {
  color: gray;
}
.intro {
  color: black;
}
```

每个 `.intro` 段落都是黑色：两条规则都命中，但 `0, 1, 0` 压过 `0, 0, 1`。

第二，_平局时，后来者胜_。两条规则优先级完全相同时，样式表里更靠下的那条生效：

```css
.intro {
  color: black;
}
.intro {
  color: gray;
}
```

段落最终是灰色的——第二条规则干脆利落地覆盖了第一条。这不是要避开的 bug，而是可以使用的工具：后面的规则有意在前面的基础上做精修。

还有一个能压倒一切的紧急开关 `!important`，而这正是它的问题所在：它压过的是整个体系而不是融入体系，于是优先级的战争只会升级，不会解决。把 `!important` 当作坏味道——解法几乎总是"写一个更具体的选择器"，而不是"抡更大的锤子"。

> **动手试一试：** 在编辑器里写一条类型规则和一条类规则，给同一个元素设不同颜色，然后把两条规则在文件里的顺序对调。顺序改变不了结果——起作用的只有优先级。

## 继承

有些属性根本不用重复声明，因为它们会沿文档树从父级流向子级。与文字相关的属性都是如此：

| 会继承        | 不会继承            |
| ------------- | ------------------- |
| `color`       | `border`            |
| `font-family` | `margin`、`padding` |
| `font-size`   | `background`        |
| `line-height` | `width`、`height`   |

这个逻辑很合理：描述*书写*的属性会被传递，因为一段文字本来就是由祖先"写"出来的；描述*盒子*的属性——边、间距、尺寸——只作用于你点名的那个元素：

```css
body {
  color: #333333;
  font-family: sans-serif;
}
```

这两行声明管住了页面上每一个字，因为所有元素都是 `body` 的后代。不需要给段落写任何规则。

当默认行为碍事时，两个关键字给你手动控制权。`inherit` 强制取父级的值，哪怕这个属性平时不流动；`initial` 把属性重置为内建默认值：

```css
a {
  color: inherit;
}
```

这条链接规则是真实的常用技巧：链接采用周围文字的颜色而不是浏览器的蓝色，对标题里或深色面板里的链接正合适。

> **动手试一试：** 在编辑器里只在 `body` 上设置 `color` 和 `font-family`。确认标题和段落免费继承了它们，然后给某个链接加 `color: inherit`，看它认祖归宗。

## 练习思路：给卡片列表上样式

起始页面有三张 article 卡片——其中一张标了 `featured`——以及一个写满 TODO 的 CSS 文件。标记已经完成，你的工作全部在样式表里。

按 TODO 标记的顺序推进：

1. 写一条 `.card` 规则：`padding: 16px`、`2px solid` 边框、`border-radius: 8px`、`margin-bottom: 12px`——三张卡片应当同时变化。
2. 用后代选择器 `.card h2` 把每张卡片的标题变成深蓝色。
3. 给 `.featured` 配金色边框色和淡黄色背景。
4. 添加 `.card:hover` 规则改变边框色，然后在预览里悬停卡片。
5. 最后给 `.featured h2` 单独配色，证明它在没有 `!important` 的情况下靠优先级赢过 `.card h2`。

第 1、2 步展示选择器的基本功；第 3 到 5 步是一场小型层叠实战。`.featured` 与 `.card` 优先级相同，所以 featured 卡片的标题需要 `.featured h2`——两个类加一个类型——才能压过"一个类加一个类型"的 `.card h2`。

每写完一条规则就预览一次，而不是五条写完再看。出了问题，你才找得到是刚写的那条规则。

> **提示：** 悬停样式是网页设计里最便宜的惊喜。一条规则、零 JavaScript，页面立刻有了生命——你喜欢的每个界面都有它。

## 常见错误

### 1. 声明之间漏写分号

少了分号，下一条声明会被解析成上一个值的一部分，然后被悄悄丢弃。

错误写法：

```css
h1 {
  color: darkblue
  font-size: 32px;
}
```

正确写法：

```css
h1 {
  color: darkblue;
  font-size: 32px;
}
```

### 2. 忘记写单位

没有单位的长度是非法的，整条声明被忽略——不报错，只是安静。

错误写法：

```css
h1 {
  font-size: 32;
}
```

正确写法：

```css
h1 {
  font-size: 32px;
}
```

### 3. 到处用 id 写样式

id 压过类，每多写一个 id，未来所有要碰同一元素的规则就多一分风险。

错误写法：

```css
#card-one {
  border: 2px solid gray;
}
```

正确写法：

```css
.card {
  border: 2px solid gray;
}
```

### 4. 在优先级之争中抡起 !important

覆盖开关今天能赢，却让明天更糟；更具体的选择器才能永远赢。

错误写法：

```css
.featured h2 {
  color: sienna !important;
}
```

正确写法：

```css
.featured h2 {
  color: sienna;
}
```

### 5. 属性或值拼写错误

CSS 从不抱怨；它忽略这一行继续走，所以拼错看起来和规则失效一模一样。

错误写法：

```css
h1 {
  colour: darkblue;
}
```

正确写法：

```css
h1 {
  color: darkblue;
}
```

### 6. 选择器太宽

光秃秃的类型选择器或 `*` 会命中页面上的一切，包括你不想碰的元素。

错误写法：

```css
div {
  border: 2px solid gray;
}
```

正确写法：

```css
.card {
  border: 2px solid gray;
}
```

> **提示：** 当一条规则"不生效"时，按顺序查三件事：属性拼写对不对、选择器是否真的匹配标记、是否有更具体的规则在覆盖。这个顺序几乎能破掉所有悬案。

## 小结

- CSS 规则由选择器加声明构成，声明是以分号结尾的 `property: value` 键值对。
- CSS 通过 `style` 属性、`style` 元素或 head 中链接的外部文件进入页面。
- 类型选择器匹配元素；类匹配名字且可复用；id 匹配唯一的那个元素。
- 组合器描述关系（`.card h2`），伪类描述状态（`:hover`、`:focus`、`:first-child`）。
- 层叠裁决胜负：优先级更高者胜，平局时靠后的规则胜——`!important` 只是最后手段。
- 文字属性沿树继承，盒子属性不会；`inherit` 和 `initial` 可以手动引导流向。
- 你用一条共享规则、一个后代选择器、一个 featured 变体和一个悬停态，完成了三卡片页面的样式。
