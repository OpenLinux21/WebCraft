## 概述

网页的绝大部分内容是文字：文章、说明、价格、按钮、脚注。第 1 课给了你文档的框架；这一课讲框架里该放什么，以及"看起来对"的文字和"有意义"的文字之间的区别。

关键词是*语义*。语义化元素指的是名字就能描述内容的元素：主标题是 `h1`，导航菜单是 `nav`，独立成篇的故事是 `article`。与之相对，通用的 `div` 什么意思都没有——它只是一个可以随便样式的空白盒子。当页面上每个盒子都是 `div` 时，只有盯着渲染结果的人眼才能分清哪块是导航、哪块是页脚。

只要"读"页面的不只是你的眼睛，语义化标签立刻带来回报。屏幕阅读器把 `nav` 播报为一个可以跳转的地标；搜索引擎给 `h1` 的权重高于一个套了样式的 `div`；阅读模式和浏览器扩展会把页面精简到只剩 `article` 和 `main`；几个月后的你也能一眼看懂语义化的文件。

本课路线图：先讲标题——它给页面提供提纲；再讲段落和行内元素——它们承载文本内部的意义；然后是塑造页面结构的语义化容器；最后在练习里动手，把一个纯 div 页面改造过来。

## 标题：页面的提纲

标题把一整块文字变成可以扫读的文档。浏览器把 `h1` 到 `h6` 渲染成逐级变小的字号，但字号是最不重要的部分：标题是*提纲*，相当于放在书前的目录。

```html
<h1>Hiking the Blue Ridge</h1>
<h2>Day one: fog, then sunshine</h2>
<h3>Morning: the switchbacks</h3>
<h3>Afternoon: the ridge line</h3>
```

两条规则能保证提纲健康。第一，每页只有一个 `h1`：它是页面的主题，其余内容都挂在它下面。第二，绝不跳级：`h3` 应该位于某个 `h2` 之下，`h2` 又位于 `h1` 之下——辅助技术会根据你的级别构建导航树，从 `h1` 直接跳到 `h4` 会被理解成内容缺失。

| 级别         | 典型用途                   |
| ------------ | -------------------------- |
| `h1`         | 页面主题，只用一次         |
| `h2`         | 页面的主要章节             |
| `h3`         | `h2` 之下的小节            |
| `h4` 到 `h6` | 更深的嵌套——实践中很少用到 |

按结构选标题级别，而不是按大小。如果浏览器默认的 `h3` 对你的设计来说太大或太小，下一模块会用 CSS 解决——绝不要因此换一个级别。

> **动手试一试：** 在内置编辑器里给自己的一周列提纲：一个 `h1`、三个 `h2` 章节，再在其中一个章节里放一个 `h3`。预览并观察浏览器如何自动安排各级字号。

## 段落、换行与分隔线

`p` 是网页的主力：一个段落说一件事，需要多少段就写多少段。浏览器会自动在段落之间留出垂直间距，屏幕阅读器也会在段落处停顿——这两点让长文变得可以消化。

```html
<p>Our first day on the trail began in thick fog.</p>
<p>By noon the sun had burned it off, and the ridge appeared.</p>
```

还有两个邻居。`br` 在段落*内部*强制换行；`hr` 画出一条分隔线，表示主题的转换——换场景了，换话题了。

```html
<address>
  50 Forest Road<br />
  Blue Ridge, NC
</address>
<hr />
<p>Next up: day two on the trail.</p>
```

这两个元素都容易被滥用。`br` 只用于换行本身就是内容一部分的文字——诗歌、地址、歌词；不要用 `br` 或 `hr` 去把内容推到页面各处。区分思想是元素的职责；区分像素是 CSS 的职责，第 4 课开始讲。

> **动手试一试：** 在编辑器里写两个段落，中间放一个 `hr`；再用一个 `br` 写一个两行的地址。体会两者的节奏差异：`hr` 分隔块，`br` 断行。

## 行内语义：文本级元素

段落内部常常需要标注单个词语：比其余部分更重要的短语、要重读的词、需要高亮的细节。HTML 为此准备了一小组*文本级*元素，每个都承载含义而不只是外观：

| 元素     | 含义                 | 默认外观 |
| -------- | -------------------- | -------- |
| `strong` | 强重要性             | 粗体     |
| `em`     | 强调、重读           | 斜体     |
| `mark`   | 与当前语境相关的高亮 | 黄色背景 |
| `small`  | 附注、细则           | 更小的字 |
| `code`   | 一段代码             | 等宽字体 |

在同一个段落里合起来用：

```html
<p>
  Pack <strong>two liters of water</strong> - the ridge has no shade. It was <em>hotter</em> than
  the forecast promised, and my <mark>favorite pen</mark> melted. The route notes live in
  <code>route/day1.txt</code>.
</p>
```

你可能还会遇到 `b`（粗体）和 `i`（斜体）。它们依然存在，但只表示"换个样子画"，而 `strong` 和 `em` 还回答了*为什么*。选择时问一个简单的问题：读出声时我会重读这个词吗？会，用 `em`。这个短语对理解句子很重要吗？是，用 `strong`。如果答案只是"我想让它换个样子"，那多半该交给 CSS。

> **动手试一试：** 在编辑器里写一个包含 `strong`、`em` 和 `mark` 的段落。预览看看三种外观的区别——同时注意，就算去掉所有样式，这些标记依然讲得通。

## 语义化容器：从 div 到 main

大多数页面共享同一种形状：顶部横幅、其下的导航、一块主内容区、侧边补充信息、底部页脚。HTML 为每个区域都准备了专用元素：

| 元素      | 角色                               |
| --------- | ---------------------------------- |
| `header`  | 引导性内容：站名、logo、标语       |
| `nav`     | 主要导航链接                       |
| `main`    | 页面的核心内容——每页只有一个       |
| `section` | 按主题划分的一组内容，通常自带标题 |
| `article` | 独立成立的内容：一篇博文、一条新闻 |
| `aside`   | 若即若离的内容：侧栏、引语         |
| `footer`  | 页脚信息：作者、版权、链接         |
| `div`     | 兜底的中性容器                     |

把它们组装成一个小博客页面：

```html
<header>
  <p>My Travel Blog</p>
  <nav>Home | Posts | About</nav>
</header>
<main>
  <article>
    <h1>Hiking the Blue Ridge</h1>
    <h2>Day one: fog, then sunshine</h2>
    <p>The trail started in fog and ended in sunshine.</p>
  </article>
  <aside>
    <p>This week: three posts from the trail.</p>
  </aside>
</main>
<footer>
  <p>Written by Sam</p>
</footer>
```

注意 `div` 并没有被禁用——当一个分组确实没有任何含义（比如纯粹为了样式而存在的包裹层）时，它就是诚实的选择。经验法则是：选名字与内容匹配的元素，只有找不到匹配时才用 `div`。

> **动手试一试：** 在编辑器里用你自己的文字搭出这个博客的形状。预览看起来几乎没变——这是正常的。变化在于结构变得机器可读，而这正是全部意义所在。

## 为什么语义化很重要

读你标记的读者有三类，其中只有一类看得到像素。使用辅助技术的人得到一张地图：`nav` 是可以跳转的地标，标题是可扫读的提纲，`main` 告诉他们正文从哪里开始。搜索引擎得到关于页面重点的线索。未来的你也得到一份会自我解释的文件。

对比同一个菜单的两种写法：

```html
<div class="menu">Home | Posts | About</div>
```

```html
<nav>Home | Posts | About</nav>
```

在浏览器眼里它们渲染得一模一样。对其余所有人来说，第一行是噪音，第二行是带名字的地标。用 `nav` 的版本，屏幕阅读器用户会听到"导航"，可以直接跳过去或跳过它；用 `div` 的版本，他们只能听完整页内容。

还有维护上的红利。语义化标记读起来就像页面的结构图，几个月后你（或同事）回来打开文件，不用运行任何东西就能看清结构。

> **动手试一试：** 在编辑器里打开本课练习的 solution 文件，只读元素名、从上到下。不读一句正文你也能还原页面的主题——这就是语义化 HTML 买到的东西。

## 练习思路：从 div 汤到语义

起始页面是一个完全用 `div` 和 class 名写成的小型旅行博客。它能渲染，看起来甚至还算像样——但在每台读它的机器眼里，页面只是四个毫无意义的盒子。

跟着 TODO 标记重构：

1. 把横幅 `div` 变成 `header`，把菜单 `div` 变成 `nav`。
2. 把正文区域包进 `main`，把文章本身包进 `article`。
3. 修正标题层级：大标题成为全页唯一的 `h1`，副标题成为 `h2`。
4. 在段落里，用 `strong` 标注 _worth every step_，用 `mark` 高亮 _fog_。
5. 把署名 `div` 变成 `footer`。

边做边预览，你会发现一个意外：页面看起来没变。这不是 bug——语义是眼睛看不见、机器看得见的东西。真正该变的是文档的读法：一个 `h1`、没有跳级、每个区域都有名字。

写完之后与 solution 对比。具体文字会与你不同，但元素名应该一一对应。

> **提示：** 拿不准该用哪个元素时，把内容大声说出来："这是站点横幅"就是 `header`；"这是那篇故事"就是 `article`；"这只是个盒子"才留在 `div`。

## 常见错误

### 1. 一页多个 h1

两个 `h1` 等于告诉屏幕阅读器和搜索引擎：这个页面有两个主题——等于没有主题。

错误写法：

```html
<h1>My Travel Blog</h1>
<h1>Hiking the Blue Ridge</h1>
```

正确写法：

```html
<h1>Hiking the Blue Ridge</h1>
<h2>Day one: fog, then sunshine</h2>
```

### 2. 标题跳级

级别是用来嵌套的；从 `h1` 直接跳到 `h3`，提纲看起来就像丢了内容。

错误写法：

```html
<h1>Hiking the Blue Ridge</h1>
<h3>Day one</h3>
```

正确写法：

```html
<h1>Hiking the Blue Ridge</h1>
<h2>Day one</h2>
```

### 3. 用 br 冒充段落

连串的 `br` 看着像段落，读起来却是一段；浏览器分不清其中的思想。

错误写法：

```html
<p>First thought.<br />Second thought.<br />Third thought.</p>
```

正确写法：

```html
<p>First thought.</p>
<p>Second thought.</p>
<p>Third thought.</p>
```

### 4. 把 b 和 i 用在 strong 和 em 的位置

老旧的视觉元素不包含任何重要性信息，工具无法区分关键词和随手的样式。

错误写法：

```html
<p>This is <b>important</b> and <i>really</i> matters.</p>
```

正确写法：

```html
<p>This is <strong>important</strong> and <em>really</em> matters.</p>
```

### 5. 什么都套 section

每个块都套 `section` 只是换了新装的 div 汤；只有当分组有主题、有标题时才用它。

错误写法：

```html
<section>My Travel Blog</section>
<section>Home | Posts</section>
```

正确写法：

```html
<header>My Travel Blog</header>
<nav>Home | Posts</nav>
```

### 6. 按默认外观选元素

因为 `h3` 字小就选它，因为 `blockquote` 有缩进就选它，等于把浏览器的默认样式焊死在结构里，一旦重新设计就全部失灵。

错误写法：

```html
<blockquote>The sidebar links</blockquote>
```

正确写法：

```html
<aside>The sidebar links</aside>
```

> **提示：** 预览抓不出语义错误——两种写法看起来都一样。请把标记读给自己听：每个元素名都应该是一个你会用来描述页面的词。

## 小结

- 标题 `h1` 到 `h6` 是页面的提纲：一个 `h1`，不跳级。
- `p` 承载段落；`br` 在段内断行；`hr` 表示主题分隔。
- `strong`、`em`、`mark`、`small` 和 `code` 给词语赋予含义——优先于 `b` 和 `i` 使用。
- `header`、`nav`、`main`、`section`、`article`、`aside` 和 `footer` 为页面各区域命名；`div` 是中性兜底。
- 语义化标记在预览里看起来一模一样，但屏幕阅读器、搜索引擎和未来的你都读得懂。
- 你把一个匿名 div 页面重构成了每个区域都有名字的文档。
