## 概述

你访问过的每一个网站——搜索引擎、新闻站，包括这门课程本身——最初都只是一个装满 HTML 的纯文本文件。浏览器本质上就是一台"读文本的机器"：它解析标签，弄清每块内容是什么，再把结果画出来。在学会美化页面、让它动起来之前，你得先会说这门母语。

HTML 的全称是 HyperText Markup Language（超文本标记语言），重点在"标记"二字。HTML 不是编程语言：它没有循环、没有条件判断、没有任何逻辑。你要做的只是给普通的文本贴标签：这一串是标题，那一串是段落，这一块是导航。浏览器读到你的标签后，决定每块内容的含义和行为。

本节课你会逐行拆解一个极小的页面，认识每个文档都离不开的那几个标签，然后在内置编辑器里组装出你的第一个完整页面。后面的每一课都建立在这副骨架之上，所以现在就把它练熟非常值得。

## HTML 到底是什么

_标签_（tag）和*元素*（element）经常被混用，但二者的区别值得花一分钟搞清楚。标签是你敲出来的记号；元素则是整个包裹：开始标签、内容、结束标签合在一起。

```html
<p>Welcome to the course.</p>
```

从左往右看：`<p>` 是开始标签，`Welcome to the course.` 是内容，`</p>` 是结束标签。中间那道斜杠告诉浏览器元素到此结束。整体——标签、内容、标签——构成一个段落元素。

浏览器并不在乎你的源码怎么排版。文件里的换行和缩进是写给人看的，不是写给它的。下面两个片段渲染出的页面完全相同：

```html
<p>Written on one line.</p>

<p>Written across several lines.</p>
```

大多数元素都遵循"打开—内容—关闭"这个模式。一旦看清它，HTML 就不再是一堆尖括号组成的墙，而只是一套贴标签的办法。事情本来就是这么简单。

> **动手试一试：** 打开内置编辑器，敲一个 `<p>` 元素写上你想说的话，再在下面加第二个。预览页面：每个段落都自动另起一行，尽管你从没要求过。这种行为属于元素本身，与你的排版无关。

## 到处都会见到的元素

HTML 元素总共有 100 多个，但一个能用的网页需要的远没有那么多。下面是这门课里你敲得最多的几个：

| 元素             | 用途                         |
| ---------------- | ---------------------------- |
| `h1` 到 `h6`     | 标题，从最重要到最次要       |
| `p`              | 一段文字                     |
| `a`              | 链接到别处                   |
| `img`            | 图片                         |
| `ul`、`ol`、`li` | 无序列表、有序列表及其列表项 |
| `footer`         | 页脚，放作者或版权信息       |
| `div`            | 通用容器，用来分组其他内容   |

不用背这张表——接下来两课你会逐一正式见到它们，手指比脑子记得更快。

> **动手试一试：** 在编辑器里把一个段落换成 `h2`，再换成 `h3`。注意每往下一级字号就小一些、字重变化也不同：浏览器为每种元素都准备了默认样式。

## 每个页面的骨架

零散的元素还不够。浏览器期望每个文档都套在同一个框架里；虽然浏览器会悄悄修复残缺的框架，但屏幕阅读器、搜索引擎和开发者工具都依赖真正的结构。下面是最小的完整 HTML5 文档：

```html
<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <title>My first page</title>
  </head>
  <body>
    <h1>Hello, world!</h1>
  </body>
</html>
```

骨架的每个部分只有一件事要做：

| 组成部分           | 职责                                        |
| ------------------ | ------------------------------------------- |
| `<!DOCTYPE html>`  | 声明这是现代 HTML5 文档，必须是第一行。     |
| `<html lang="en">` | 根元素，包住其他一切；`lang` 声明页面语言。 |
| `<head>`           | 存放*关于*页面的信息——不会直接显示。        |
| `<body>`           | 存放读者真正看到的一切。                    |

doctype 看起来像块化石——它确实是——但它不可省略：没有它，浏览器会切换到"怪异模式"（quirks mode），按陈旧规则渲染，日后你的 CSS 会悄悄出错，而且很难追查到这一行。每次都先敲它。

> **动手试一试：** 把骨架粘进编辑器，改一改 `lang` 的值和标题文字，然后预览。标签页标题立刻更新——这是你第一次控制浏览器本身，而不只是页面。

## head 里面：页面元信息

head 是页面的后台。读者看不到它，但它告诉浏览器如何对待这个文档。几乎所有页面的 head 里都有两个孩子，外加几个常见成员：

```html
<head>
  <meta charset="UTF-8" />
  <meta name="viewport" content="width=device-width, initial-scale=1" />
  <title>Field Notes: September</title>
  <meta name="description" content="Short walks, long thoughts, and what I noticed on the way." />
</head>
```

`meta charset` 声明字符编码，让每个符号、重音字母和 emoji 都能安然无恙地从文件走到屏幕。把它放在 head 的第一位。

`title` 不是页面上的标题。它是显示在浏览器标签页、书签和搜索结果里的名字，所以要写得具体：_My page_ 对谁都没帮助，而 _Field Notes: September_ 能让人和搜索引擎都准确预期内容。

viewport 那一行让页面在手机上表现得体。现在先记住它就好——布局模块还会回来讲——但从第一天就带上它，因为以后补写很容易忘。

> **动手试一试：** 在编辑器里，在 title 之下加一条 `meta` description，再改改 title 并预览。界面上什么都没变——这正是重点：head 在幕后工作。

## 嵌套、属性与空元素

元素可以住在别的元素里面。嵌套就是 HTML 表达结构的方式：列表项在列表里，标题在横幅里。规则只有一条——内层元素先关闭：

```html
<body>
  <main>
    <h1>Cake recipe</h1>
    <p>Preheat the oven <strong>before</strong> you mix anything.</p>
  </main>
</body>
```

元素还可以携带属性（attribute）：写在开始标签内部的 `name="value"` 键值对。你已经在 `html` 元素上见过 `lang="en"`。后面还会遇到很多——链接用的 `href`、图片用的 `src`，以及负责样式和脚本的 `class` 与 `id`。

```html
<p class="intro" id="welcome">Some text.</p>
```

少数元素根本没有内容，因此永远不写结束标签。它们叫做空元素，或 void 元素：

```html
<meta charset="UTF-8" />
<hr />
<br />
```

`meta` 携带信息，`hr` 画一条分隔线，`br` 强制换行。`>` 前的那道斜杠在 HTML5 里可写可不写——`<br>` 和 `<br />` 都合法——但写上它，元素一眼看去就是空的。

> **动手试一试：** 在编辑器里往段落中嵌套一个 `strong`，再在后面加一个 `hr` 并预览。如果页面有一部分凭空消失，多半是内层元素的关闭顺序出了错。

## 注释与空白

HTML 有注释语法。与周围的代码不同，注释会被浏览器完全忽略。它们是写给人类的：给未来的自己留便条、给同事做解释，或者临时停用一行你还不舍得删的代码。

```html
<p>Visible text.</p>
<!-- This sentence never appears on the page. -->
```

空白也是同样的道理。浏览器会把连续的空格、制表符和换行折叠成一个空格，所以跨了三行源码的段落依然渲染成一句连贯的话：

```html
<p>This paragraph has extra spaces and runs across two source lines.</p>
```

源码要写得让人读得舒服——该缩进就缩进，该注释就注释，能一行一个元素就一行一个。剩下的交给浏览器。

> **动手试一试：** 在编辑器里给标题上方加一条注释，再往某个段落的两个词之间塞上二十个空格，然后预览。注释消失了，空格也缩成了一个。

## 练习思路：你的第一个完整页面

起始文件已经有 doctype、`lang` 属性和一个声明了字符编码的 head——但页面还没有 title，body 也没有内容。你的任务是把它补成一份可以交给任何人的文档。

按 TODO 标记的顺序推进：

1. 在 head 里添加 `title` 元素，名字要让你在一排标签页里也能一眼认出。
2. 在 body 里添加一个向读者问好的 `h1`。
3. 标题下方加一个 `p`，用两三句话介绍你自己。
4. 最后用一个 `footer` 写上你的名字和今天的日期。

做的过程中要多预览。两个快速检查能说明文档是健康的：标签页显示你的标题；每块内容恰好出现一次。如果内容缺失，找找有没有打开了却没关闭的标签；如果出现了两次，多半是不小心把某个元素嵌进了另一个元素里。

参考答案不需要任何花哨技巧。一副完整骨架加上 body 里的三个孩子，*就是*本课的全部——写完之后对照 solution 文件：即便文字不同，标签也应该一一对应。

> **提示：** 从现在起，本课程的每个练习都从同一副骨架出发。如果不看资料也能敲出 doctype、`html`、`head`、`meta charset`、`title` 和 `body`，你已经把 Web 开发里最重复的部分变成肌肉记忆了。

## 常见错误

### 1. 忘记写结束标签

浏览器会自行恢复，但方式往往出人意料——少一个 `</p>` 可能吞掉它后面的元素。

错误写法：

```html
<p>Welcome to the course.</p>
```

正确写法：

```html
<p>Welcome to the course.</p>
```

### 2. 嵌套顺序颠倒

内层元素必须先关闭；标签交叠会让所有人困惑，包括浏览器。

错误写法：

```html
<p>Text with <strong>emphasis</p></strong>
```

正确写法：

```html
<p>Text with <strong>emphasis</strong></p>
```

### 3. 把可见内容放进 head

head 只放元信息；放在那里的内容要么消失，要么被搬去莫名其妙的位置。

错误写法：

```html
<head>
  <p>This text never shows up.</p>
</head>
```

正确写法：

```html
<body>
  <p>This text shows up.</p>
</body>
```

### 4. 省略 doctype

页面照样渲染，但进入了怪异模式，CSS 会以各种方式出错，而很难想到根由是少了一行。

错误写法：

```html
<html lang="en">
  <head></head>
</html>
```

正确写法：

```html
<!DOCTYPE html>
<html lang="en"></html>
```

### 5. 属性值不加引号

属性遵循 `name="value"` 的格式；少写一个引号，浏览器会把标签后面的内容一起吞掉。

错误写法：

```html
<p class="intro">Text.</p>
```

正确写法：

```html
<p class="intro">Text.</p>
```

### 6. 把块级元素塞进段落

`p` 里只能放文本和行内元素；浏览器遇到标题或 div 会强行把段落截断。

错误写法：

```html
<p>Introduction line <h2>Details</h2></p>
```

正确写法：

```html
<p>Introduction line</p>
<h2>Details</h2>
```

> **提示：** 如果预览时内容突然消失，原因几乎总在前两种错误里。从缺失的位置往前读代码，逐个确认标签都已按顺序关闭。

## 小结

- 元素由开始标签、内容和结束标签组成；`meta`、`hr`、`br` 这类空元素没有结束标签。
- 每个文档都需要 doctype、带 `lang` 的唯一 `html` 根元素、一个 `head` 和一个 `body`。
- head 存放 `meta charset`、`title`、viewport 之类的元信息；body 存放一切可见内容。
- 属性是写在开始标签里的 `name="value"` 键值对。
- 注释和多余空白不会到达读者——源码是写给人的。
- 你已经在内置编辑器里搭建并预览了一个完整的 HTML5 文档。
