## 概览

可访问性常被想象成最后的检查清单，一层在项目收尾时补上的合规装饰。更准确的理解是：它是你从第一行代码起就写下的标记的属性。用户与网页交互的方式远不止鼠标一种：屏幕阅读器用户按标题和地标导航，运动障碍用户完全依赖键盘，而标签、对比度、可预期的焦点对每个人都有益——尤其是在烈日下看手机的那一刻。

令人振奋的是：可访问性的大部分工作不是额外付出，而是*选对元素*。一个 `<button>` 天生响应 Enter 和 Space、被朗读为按钮、可以获得焦点；而一个假扮按钮的 `<div>` 需要你徒手把这些全部重建。所以顺序是：先语义，再键盘，最后才用 ARIA 补缺口。

本课你将打磨这三个直觉，并把它们应用到一个经典组件上：disclosure——那个"展开更多"的小控件——让它完全可被键盘操作，并被屏幕阅读器正确播报。

## 语义：免费的可访问性

屏幕阅读器不是逐字朗读你的页面，它提供结构化导航："跳到 main"、"列出所有标题"、"列出所有按钮"。这些结构来自你写的元素。语义化 HTML 是你花过的最便宜的可访问性预算：

| 元素                                       | 辅助技术得到什么                 | 常见的错误替代品              |
| ------------------------------------------ | -------------------------------- | ----------------------------- |
| `header`、`nav`、`main`、`aside`、`footer` | 在页面区域间跳跃的地标           | 一片匿名的 `<div>` 海洋       |
| 有序的 `h1` 到 `h6`                        | 可快速浏览的文档大纲             | 用加粗段落冒充的标题          |
| `button`                                   | 角色、Enter/Space 激活、可聚焦   | `<div onclick>`               |
| `a href`                                   | "链接"播报、Enter 激活、中键行为 | `<button onclick="location">` |
| `ul` / `ol` / `li`                         | 提前播报列表项数量               | 一排排 `<div>`                |
| `label`                                    | 每个输入框的可访问名称           | placeholder 文本              |

```html
<body>
  <header>
    <nav aria-label="主导航">…</nav>
  </header>
  <main>
    <h1>页面标题</h1>
    <section aria-labelledby="summary-heading">
      <h2 id="summary-heading">摘要</h2>
    </section>
  </main>
  <footer>…</footer>
</body>
```

> **试一试：** 在内置编辑器里用 Tab 走一遍练习起始页，你会发现还没有执行任何 JavaScript，触发按钮就已经可以到达——语义在第一行 JS 运行之前就已生效。

同样的原则也决定点击行为：原地执行动作的是 `<button>`；跳转到别处的是 `<a href>`。按行为选择，而不是按外观选择——CSS 可以把两者修饰成任何样子。

## 焦点与键盘

键盘用户用 Tab（下一个控件）、Shift+Tab（上一个）和 Enter 或 Space（激活）在页面中移动。他们访问控件的顺序是 **DOM 顺序**，而不是 CSS 创造出的视觉顺序。一个看起来井井有条、DOM 里却乱成一团的布局是陷阱：永远让 DOM 顺序与阅读顺序保持一致。

`tabindex` 属性可以调整它，但要克制：

| 取值 | 效果                                    | 使用时机               |
| ---- | --------------------------------------- | ---------------------- |
| 缺省 | 原生元素参与 Tab 遍历；`div` 等则不参与 | 几乎总是               |
| `0`  | 把元素按 DOM 位置加入 Tab 序列          | 自定义组件需要可聚焦时 |
| `-1` | 只能被脚本聚焦，不进 Tab 序列           | 需要程序化移动焦点时   |
| 正数 | 承诺一套手工顺序，成为维护债            | 实践中：永远别用       |

焦点指示器是键盘用户的鼠标指针——你不会藏起鼠标光标，也就不该藏起焦点。现代工具是 `:focus-visible`：它只在浏览器判断为键盘焦点时显示轮廓，鼠标用户点击时不会看到圆环：

```css
.disclosure-trigger:focus-visible {
  outline: 3px solid #1d4ed8;
  outline-offset: 2px;
}
```

> **提示：** 如果你在任何状态下移除了默认 outline，就必须提供替代品。`outline: none` 而什么都不补，是 CSS 里破坏力最大的单行修改之一。

> **试一试：** 用 Tab 走一遍练习起始页，然后加上面的 `:focus-visible` 规则，观察圆环恰好在你用键盘到达时出现——点击时则不会。

## 替代文本与可访问名称

屏幕阅读器猜不出一张图显示了什么、一个图标按钮做什么；它只能朗读元素的**可访问名称**。起这个名字是你的职责：

- **有意义的图片**的 `alt` 要传达与视觉相同的信息。"第三季度销售额上升 20% 的折线图"——而不是"图表"。
- **装饰性图片**用 `alt=""`，让屏幕阅读器直接跳过。空 alt 是刻意的声明，不是遗忘。
- **纯图标控件**——放大镜提交按钮、关闭对话框的 X——用 `aria-label` 命名：

```html
<button aria-label="搜索">
  <svg aria-hidden="true" viewBox="0 0 24 24">…</svg>
</button>
```

两个细节值得刻在脑子里。图标上的 `aria-hidden="true"` 表示"这是装饰，跳过它"——否则屏幕阅读器可能先播报一个空图形再读到名称。另外，可访问名称要把重要的词放在开头，因为屏幕阅读器用户经常按名称在控件间跳跃。

> **试一试：** 把鼠标悬停在练习的触发按钮上，把它的文字读给自己听。如果看不见旁边的箭头图标，这句话还成立吗？不成立就补一个 `aria-label`。

## 务实的 ARIA

ARIA（Accessible Rich Internet Applications）是一组属性，用来在 HTML 语义力所不及的地方打补丁：会变化的状态、HTML 没有对应元素的组件。它的第一法则大名鼎鼎：**如果原生元素能胜任，就不要用 ARIA。**ARIA 不添加行为，只添加播报。`role="button"` 的 div 在 Enter 键下依旧毫无反应——你只是写下了一个 CSS 无法兑现的承诺。

在原生 HTML 真正的缺口处，一小组属性覆盖了绝大多数需求：

| 属性              | 放在     | 播报内容                     | 典型场景                 |
| ----------------- | -------- | ---------------------------- | ------------------------ |
| `aria-label`      | 任意控件 | 一个替代或补充可见文字的名称 | 纯图标按钮、区域         |
| `aria-expanded`   | 触发按钮 | 被控对象当前是否展开         | disclosure、菜单、手风琴 |
| `aria-controls`   | 触发按钮 | 它展开的是哪个元素（按 id）  | 把触发器与面板关联       |
| `aria-hidden`     | 装饰内容 | "完全跳过这一块"             | 图标字体、重复文本       |
| `aria-labelledby` | 区块     | 取自某个标题 id 的名称       | 不加额外文字就给区块命名 |

disclosure 组件用的正是核心模式——一个与现实保持同步的状态属性：

```js
toggleButton.addEventListener('click', () => {
  const isOpen = panel.hidden;
  panel.hidden = !isOpen;
  toggleButton.setAttribute('aria-expanded', String(!isOpen));
});
```

> **提示：** `aria-expanded` 放在触发器上，而不是面板上。屏幕阅读器用户此刻正停在按钮上问"你负责展开的东西现在开着吗？"——答案就该在这个位置。

## 实战练习：可用键盘操作的 disclosure

起始页有一个带箭头的触发按钮和下方的内容面板，但什么都还不能用。从思路上看，构建步骤如下：

1. **接通切换。** 一个函数同时翻转 `panel.hidden`，并把 `aria-expanded` 设为对应的字符串。两者永远一起变化。
2. **在界面上反映状态。** 让箭头旋转（在按钮上加一个 CSS 类，用 `transform: rotate`），让明眼用户也看得到状态——ARIA 播报与视觉暗示必须一致。
3. **键盘免费到手——去验证。** 触发器是真正的 `<button>`，Enter 和 Space 本来就会触发 `click`。用 Tab 移过去试一试；如果激活不了，问题出在标记里，而不是 JS 里。
4. **让焦点可见。** 给触发器加上 `:focus-visible` 轮廓，并确认键盘聚焦时它能出现。
5. **诚实地命名。** 让按钮在 HTML 里就带着初始值 `aria-expanded="false"`，并确认面板初始就有 `hidden`——在任何交互之前，状态就必须是正确的。

提醒一下分寸：disclosure 展开的内容之后要继续可用。这正是面板直接使用 `hidden` 属性、而不做焦点陷阱的原因——键盘用户可以像浏览页面其他内容一样自然地 Tab 进展开后的内容。

## 常见错误

**1. 把点击处理器挂在非交互元素上。** 带点击监听的 `div` 对键盘不可见，对屏幕阅读器也一声不吭。

```html
<!-- 错误：不能聚焦、不能 Enter、没有播报 -->
<div onclick="toggle()">显示详情</div>

<!-- 正确：这一切都是免费的 -->
<button type="button">显示详情</button>
```

**2. 删掉焦点轮廓。** 键盘用户从此不知道自己在页面的哪个位置。

```css
/* 错误：键盘光标消失了 */
button:focus {
  outline: none;
}

/* 正确：清晰的圆环，且只在键盘聚焦时出现 */
button:focus-visible {
  outline: 3px solid #1d4ed8;
}
```

**3. ARIA 不知道的状态。** 面板开了又关，按钮却从不说明——屏幕阅读器用户无法判断点击是否生效。

```html
<!-- 错误：触发器不播报任何状态 -->
<button type="button">显示详情</button>

<!-- 正确：触发器报告面板状态 -->
<button type="button" aria-expanded="false">显示详情</button>
```

**4. 无意义的 alt 文本。** "图片""照片"或文件名浪费了盲人用户了解该内容的唯一通道；给装饰图写一大段 alt 同样是噪音。

```html
<!-- 错误：alt 没有提供任何增量信息 -->
<img src="divider.svg" alt="一条灰色的水平分隔线" />

<!-- 正确：明确声明装饰可被跳过 -->
<img src="divider.svg" alt="" />
```

**5. 用正数 tabindex 修补 DOM 顺序。** 手工编号 `tabindex="1"`、`2`、`3`，布局一变就全线崩塌。

```html
<!-- 错误：多出一套需要人工维护的 Tab 顺序 -->
<input tabindex="2" />
<input tabindex="1" />

<!-- 正确：在 HTML 里按正确顺序摆放元素 -->
<input id="first" />
<input id="second" />
```

**6. 用 ARIA 给错误的元素打补丁。** `role="button"` 改变的只是播报内容，不是行为。如果元素既不能聚焦也不能响应按键，任何角色都救不了它——先换成真正的元素。

## 小结

- 语义化 HTML 是地基：地标、标题、列表和原生控件免费提供结构与行为。
- 键盘可操作性是一等公民：遵循 DOM 顺序，克制地使用 `tabindex`，提供可见的 `:focus-visible` 焦点环。
- 每张有意义的图片、每个纯图标控件都需要人来撰写的可访问名称；装饰内容要显式隐藏。
- ARIA 用来填补真实缺口——`aria-expanded`、`aria-label`、`aria-hidden`——但它永远不能替代选对元素。
- 在改变 UI 的同一个函数里同步状态属性，让播报永远没有说谎的机会。
