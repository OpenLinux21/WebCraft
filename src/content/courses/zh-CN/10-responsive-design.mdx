## 概述

你的预览窗格宽度很舒服，但页面真正会被阅读的地方是：挤在火车座位上的手机、办公笔记本、巨大的显示器。**响应式设计**的目标是写出一个能适配所有这些屏幕的页面——不是做三个网站，而是同一套 HTML 和 CSS，里面有些规则会在屏幕变化时自动启用。

好消息是：学完 Flexbox 和 Grid，你手里已经握着大部分工具。流式宽度、`flex-wrap`、`auto-fit` 网格能*独立*完成相当多的自适应。媒体查询是收尾的那一层，不是地基——它只需要修复流式布局搞不定的部分。

本节课你会认识视口 meta 标签、学会 `@media` 的语法、练习桌面优先的覆盖模式，并遇见让文字连续缩放的 `clamp()`。随后练习要求你让一个新闻页面安然完成从桌面宽度到手机宽度的旅程。

## 先有视口与流式布局

响应式的第一块 CSS 其实根本不是 CSS——它是 HTML 里的一个 meta 标签。没有它，移动浏览器会假装页面有 980px 宽然后整体缩小，制造出人人厌恶的小字体验：

```html
<meta name="viewport" content="width=device-width, initial-scale=1" />
```

视口搞定之后，下一个习惯是**流式布局**：宽度要能弯，不能一碰就断。百分比、`max-width`、`fr` 单位、flex 换行，这些在任何断点出现之前就已经在干活了。

```css
.container {
  max-width: 880px; /* 桌面上够宽敞 …… */
  margin: 0 auto; /* …… 居中，低于 880px 时自然变窄 */
  padding: 0 16px;
}

img {
  max-width: 100%; /* 永远不比容器宽 */
  height: auto;
}
```

照这个思路搭出来的页面已经能扛住大幅收缩：容器跟着变窄、图片跟随盒子、换行的 flex 行自动重排。只有当元素真的挤不下去时——比如两栏已经窄到没法读——断点才有出场的必要。

> **在编辑器中试一试：** 确认启动页有视口 meta 标签，然后*在添加任何媒体查询之前*把预览从宽拖到窄。记下布局开始变难看的确切宽度——你的断点就该放在那里。

## 编写媒体查询

媒体查询把 CSS 规则包进一个条件：这些声明**只在条件成立时**生效。你天天要用的两个条件是 `max-width`（不超过这个宽度）和 `min-width`（从这个宽度往上）：

```css
/* 桌面优先：小屏幕的规则放在最后 */
.layout {
  display: flex;
  gap: 24px;
}

.sidebar {
  flex: 1;
}
.article {
  flex: 2;
}

@media (max-width: 720px) {
  .layout {
    flex-direction: column; /* 堆叠两栏 */
  }
}
```

这里有两种流派。**桌面优先**把宽敞布局写成默认值，再用 `max-width` 查询向下覆盖。**移动优先**从堆叠的手机布局起步，用 `min-width` 查询向上加宽敞。两者都成立，关键是选定一个并保持一致——因为媒体查询并不比普通选择器更"特殊"，**顺序决定胜负**，覆盖规则必须写在被覆盖规则之后。

```css
/* 移动优先的写法 */
.layout {
  display: flex;
  flex-direction: column;
  gap: 24px;
}

@media (min-width: 720px) {
  .layout {
    flex-direction: row;
  }
}
```

媒体查询能测的不只是宽度——`orientation: portrait`、`prefers-reduced-motion`、`hover: none` 都可以，还能用 `and` 组合条件。本课程里宽度查询是主力，其他条件知道存在即可。

> **在编辑器中试一试：** 添加上面的堆叠查询，然后把预览缓缓拖过 720px 这条线。布局应当恰好翻转一次，中间没有任何跳动。

## 用 clamp() 实现流式文字

字号是个特殊难题。固定的 `font-size` 在手机上显得巨大、在显示器上显得很小；在每个断点改一遍字号，意味着永远都在写新的媒体查询。`clamp()` 在下限和上限之间连续缩放：

```css
h1 {
  /* 最小 1.6rem，首选值为视口宽度的 5%，最大 2.5rem */
  font-size: clamp(1.6rem, 5vw, 2.5rem);
}
```

函数接收三个值：最小值、*首选*值和最大值。首选值——这里是 `5vw`，即视口宽度的百分之五——负责缩放，两侧的值负责夹住它。视口宽度在 32px 到 50px 之间时标题平滑变大，超出后保持不动。

同样的技巧也适用于 padding 和间距：`padding: clamp(12px, 3vw, 32px)` 让页面的呼吸感随屏幕长大。原则是：媒体查询留给**结构性变化**（堆叠、隐藏、重排），连续的尺寸变化交给 `clamp()`。

| 工具                    | 最适合的场景             | 断点之间的表现         |
| ----------------------- | ------------------------ | ---------------------- |
| 固定 `px`               | 发丝线、图标、边框       | 永远不变               |
| `rem`                   | 基础字号、间距           | 只随用户设置变化       |
| `vw`                    | 跟随视口的原始缩放       | 一直变——可能小到没法读 |
| `clamp(下限, 值, 上限)` | 标题、Hero 文案、padding | 在上下限之间平滑缩放   |

> **在编辑器中试一试：** 给页面标题加 `font-size: clamp(1.6rem, 5vw, 2.5rem)` 然后拖动预览。看字号在没有任何断点的情况下平滑滑动，再把 `5vw` 换成 `10vw`，看上限更早接管。

## 按断点改造与移除内容

响应式不只是调尺寸——有时正确的做法是*重构*：分栏堆叠、导航折叠、侧栏挪到正文下方。有时正确答案是*移除*：促销框、标语、装饰栏在小屏幕上用 `display: none` 直接消失。

```css
/* 桌面端：促销框待在侧栏里 */
.promo {
  background: #fef3c7;
  padding: 12px 16px;
  border-radius: 8px;
}

@media (max-width: 720px) {
  .promo {
    display: none; /* 手机上消失，不留痕迹 */
  }
}
```

`display: none` 是这里的正解：元素完全不占空间；`visibility: hidden` 则只是藏起像素、留下布局空洞。每个断点可以过一遍这份清单：

1. 有内容溢出盒子吗？用流式宽度或堆叠来修。
2. 有东西小到点不中吗？在触屏上放大点击区域。
3. 有东西不再值它的那块地方吗？隐藏它。
4. 阅读顺序还通顺吗？堆叠后的栏是自上而下阅读的，所以 HTML 里正文要写在侧栏前面。

> **在编辑器中试一试：** 在 720px 处隐藏促销框，然后把 `display: none` 换成 `visibility: hidden` 对比一下——一个留下空洞，另一个不会。

## 练习思路

练习是一个新闻页面：正文和侧栏左右并排，侧栏里有个促销框，页面上有一条大标题。启动样式表用 flex 搭好了桌面布局，你的任务是补上响应式这一层：

1. **检查地基。** 页面应该已经有视口 meta 标签和流式宽度（`max-width`、百分比）。如果你一条查询都没写就有内容溢出，先修流式布局。
2. **找到天然断点。** 拖窄预览盯着那两栏。在它们开始变得难以阅读的宽度附近——启动代码建议 720px——就是媒体查询该出现的地方。
3. **堆叠布局。** 在样式表*末尾*添加 `@media (max-width: 720px)`，把布局容器切到 `flex-direction: column`，并确保两栏都占满整行宽度。
4. **移除与缩小。** 在同一个查询里用 `display: none` 藏起促销框，并把标题字号换成 `clamp()` 让它连续缩放。
5. **验证两种状态。** 把预览从两个方向拖过断点。布局应当在一个宽度上干净地翻转，中间任何位置都不溢出。

忍住别加一堆断点。这个页面两种状态——桌面与堆叠——就够了，剩下的交给流式布局。两种状态都看起来正确后，再去对比参考答案。

## 常见错误

### 1. 缺少视口 meta 标签

没有这个 meta 标签，移动浏览器按虚假的 980px 宽度渲染再整体缩小，你的媒体查询在真机上看起来就像从未生效。

```html
<!-- 错误：移动浏览器假装这是桌面宽度 -->
<title>News</title>

<!-- 正确：页面宽度跟随设备 -->
<meta name="viewport" content="width=device-width, initial-scale=1" />
```

### 2. 媒体查询写在了它要覆盖的规则之前

媒体查询不会提高优先级——同优先级时后面的规则赢。写在文件顶部的查询会被下面的默认值悄悄覆盖。

```css
/* 错误：下面的默认值赢了，什么也没堆叠 */
@media (max-width: 720px) {
  .layout {
    flex-direction: column;
  }
}
.layout {
  flex-direction: row;
}

/* 正确：覆盖规则放最后 */
.layout {
  flex-direction: row;
}
@media (max-width: 720px) {
  .layout {
    flex-direction: column;
  }
}
```

### 3. 什么都想靠断点解决

媒体查询叠在流式布局上才好用；流式布局缺失时它们会大声失败。如果内容在断点*之间*溢出，说明宽度写死了，得让它能弯。

```css
/* 错误：跳变，而且中间会溢出 */
.article {
  width: 640px;
}

/* 正确：断点之间保持流式 */
.article {
  width: 100%;
  max-width: 640px;
}
```

### 4. 用 visibility: hidden 冒充 display: none

`visibility: hidden` 藏起像素却保留占位——被"移除"的促销框会在侧栏里留下一个洞。

```css
/* 错误：盒子没了，位置还在 */
.promo {
  visibility: hidden;
}

/* 正确：盒子连同位置一起消失 */
.promo {
  display: none;
}
```

### 5. 字号只用 vw 单位

视口单位缩放没有边界：手机上 `5vw` 小到没法读，显示器上大到荒唐。永远用 `clamp()` 包住它们。

```css
/* 错误：手机上极小，显示器上巨大 */
h1 {
  font-size: 5vw;
}

/* 正确：在上下限内缩放 */
h1 {
  font-size: clamp(1.6rem, 5vw, 2.5rem);
}
```

### 6. 只测断点的确切宽度

只看 719px 和 721px 远远不够——大多数"生活"发生在断点*之间*。在整个范围内连续拖动，盯住溢出。

```css
/* 开发期间一个好用的体检手段 */
* {
  outline: 1px solid rgb(239 68 68 / 0.3);
} /* 上线前记得删掉 */
```

## 小结

- 视口 meta 标签排在第一位；流式宽度（`max-width`、百分比、`fr`、换行）在任何查询之前就完成了大部分适配。
- `@media (max-width: 720px)` 对"不超过该宽度"生效；`min-width` 是移动优先的向上写法——选定一个方向并保持一致。
- 媒体查询看顺序不看优先级：覆盖规则要放在样式表末尾。
- `clamp(下限, 首选, 上限)` 让字号和间距连续缩放，把查询留给结构性变化。
- 每个断点要么重构（堆叠分栏）要么移除（`display: none`）内容，最后在整个范围内拖动验证。
